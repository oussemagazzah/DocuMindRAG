1. Overview

DocuMindRAG is a Retrieval-Augmented Generation (RAG) application that allows users to upload PDF documents and ask natural language questions, receiving accurate answers with exact page citations.

Key Value Proposition: Every answer is grounded in the source document with page-level citations, eliminating hallucination and enabling verification.

Core Capabilities

  • PDF upload and processing with page-aware chunking
  • Hybrid retrieval (dense + sparse vectors) for maximum recall
  • Cross-encoder reranking for precision
  • LLM-powered answer generation with citation enforcement
  • Real-time query interface with source attribution

2.1 Ingestion Pipeline

The ingestion pipeline transforms raw PDFs into searchable vector embeddings:

  1. PDF Parsing (PyMuPDF): Extract text from each page
  2. Page-Aware Chunking: Split pages into 512-token chunks with 128-token overlap
  3. Embedding Generation: Convert chunks to 384-dim dense vectors using all-MiniLM-L6-v2
  4. Sparse Vector Generation: Build BM25-style sparse vectors for keyword matching
  5. Qdrant Upsert: Store dense + sparse vectors with payload metadata
  6. SQLite Storage: Store document and chunk metadata for citation retrieval

3. Retrieval Pipeline

The retrieval pipeline finds the most relevant chunks and generates grounded answers:

3.1 Hybrid Search

Query → [Dense Search] + [Sparse Search] → RRF Fusion → Rerank → Top-K Results (Semantic) (Keywords) (Combine) (Precision) (Final)
StepMethodPurposeTop-K
1Dense SearchSemantic similarity via embeddings20
2Sparse SearchExact keyword matching (BM25)20
3RRF FusionCombine ranked lists (k=60)20
4Cross-Encoder RerankPrecision reranking5

3.2 Reciprocal Rank Fusion (RRF)

RRF combines results from multiple retrieval methods without requiring score normalization:

score(d) = Σ 1/(k + rank_i(d))

where:
  k = 60 (standard constant)
  rank_i(d) = rank of document d in result list i

3.3 Answer Generation

The final answer is generated by an LLM with strict citation rules:

  • Context chunks are formatted with page markers: {text} [p.X]
  • System prompt enforces citation requirements
  • LLM must cite page numbers for every factual claim
  • If context is insufficient, LLM says "I don't have enough information"
Citation Prompt: "For every factual claim, cite the page number like [p.X] or [p.X, p.Y]. If the context doesn't contain enough information, say so explicitly."

5.3 Chunking Strategy

  • Target chunk size: 512 tokens (~2000 characters)
  • Overlap: 128 tokens (25%)
  • Max chunk size: 1024 tokens
  • Merging: Small pages merge with next page until threshold

7. Deployment & Setup

Prerequisites

  • Python 3.11+
  • Docker Desktop (for Qdrant)
  • Ollama (for local LLM)

Quick Start

# Clone and enter the project
cd DocuMindRAG

# Create virtual environment
python -m venv venv
venv\Scripts\activate   # Windows
# source venv/bin/activate  # macOS/Linux

# Install dependencies
pip install -r requirements.txt

# Copy environment config
cp .env.example .env
# Edit .env with your API keys

# Start Qdrant
docker compose up -d

# Pull LLM model (optional, for local inference)
ollama pull qwen2.5:0.5b

# Start the server
python run.py

8. Design Decisions

Why Hybrid Retrieval?

Dense retrieval captures semantic similarity but may miss exact keyword matches. Sparse retrieval (BM25) excels at keyword matching but lacks semantic understanding. RRF fusion combines both strengths without requiring score normalization.

Why Cross-Encoder Reranking?

Cross-encoders process query-document pairs jointly, providing higher accuracy than bi-encoders used in initial retrieval. The 200-500ms overhead is acceptable for the quality improvement.

Why Page-Aware Chunking?

Standard text splitting breaks page boundaries, making citations inaccurate. Page-aware chunking preserves page information, enabling exact page-level citations in answers.

Why RRF over Linear Combination?

RRF is parameter-free and robust to different score distributions across retrieval methods. Linear combination requires tuning weights and normalizing scores.
